# UX decluttering and the matrix dialog — plan (2026-11-02)

Status: **plan only, nothing started.** Reviewed before any code moves. Owners are marked `[here]` (this desktop, the only
writer of `zimage_ui.py`) and `[4060]` (the RTX 4060 laptop, which measures and validates only — see §7 for why it gets no
implementation).

## 1. Goal, and what this is not

**Goal:** fewer always-visible controls, the same reachable actions, and one place where a parameterised bulk action says
honestly what it will cost (count, minutes, and a warning when the choice is expensive).

**Not:** no redesign of the columns, no new state machine, no change to grouping or lineage, no web-app feature work (parity
note only), and **no action gets two homes** — a control that moves is deleted in the same commit that adds its menu item.


Folder-level commands live on **one** surface — the open folder's title — so the folder tile menu stays short. **Moved and
deleted in the same commit:** `Delete…`, `Recover…`, `Gallery…`, `Caption…`, `A/B…` leave the pane; `Session log…` and

Rule: **menu = verb, dialog = arguments.** A menu label containing parameters is a sign the dialog is missing.

## 4. Matrix dialog

### 4.1 Core first (pure, no Tk) — `[here]`

`matrix.py`: `window(current, …) -> (lo, hi)`, `values(lo, hi, step)`, `plan(values, bases)`, `sheet_grid(n)`.
Tests in `test_matrix.py`: the 95 → 80–100 case, the shift-not-truncate rule, the narrow-range fallback, chip count,
name suffixes, sheet packing with padded cells.

```
lo = clamp(current − 10, MIN, MAX);  hi = clamp(current + 10, MIN, MAX)
if hi − lo < 20:                      # hit a wall: shift the window, never truncate it
    hi = min(MAX, lo + 20) if lo == MIN else hi
    lo = max(MIN, hi − 20) if hi == MAX else lo
step = 1                               # 95 % → 80–100 (21 values), not 85–100 (16)
```
Narrow legal range (< 20 units): **10 steps across the whole legal range**, with the computed step *shown*.

### 4.2 The dialog — `[here]`

| element | content | acceptance |
|---|---|---|
| summary line | `21 strengths × 1 base = 21 renders · 40→60 by 1 · base: alley.png` | one sentence answers "what will this do" |
| strengths | from / to / step labelled `%`; live chips, click to exclude | a 95 % strength opens at 80–100 with 21 chips |
| presets | `±10 by 1 (21)` default · `±10 by 2 (11)` · `full range (N)` | the coarse preset halves the count in one click |
| bases | current base, base pool, or *each selected picture* (thumbnails) | empty list gives a reason, not a dead button |
| cost | `21 × 14.3 s ≈ 5 min 0 s` from measured wall time for this card+model+size | the estimate is shown **before** any render starts |
| contact sheet | `[ ] also compose a contact sheet (3×3 → 1536²)`, **default off**, costed separately (~0.1 s, not in the render estimate) | grid is the smallest square ≥ N; empty cells padded, never stretched |
| profile row | model · size · steps, **read-only** | the dialog cannot change a second copy of a profile decision |
| actions | `Enter` start · `Esc` cancel · `reset to ±10` · last values remembered | reopening needs no re-entry |
| naming | `<stem>-s<value>.png`; sheet `…-sheet-3x3.png` with a sidecar listing members | gallery, ranking and A/B can tell candidates apart |

## 5. The hunt warning — `[here]`

Fires when all three hold: `size` is the profile's largest (1024 today) **and** the active model is not the fastest measured
for this card at that size **and** `count × Δwall` exceeds 10 minutes.

```
21 renders at 1024 px on flux3 klein 4b ≈ 50 min 0 s
   fastest measured at this size: z-image turbo ≈ 5 min 0 s
[ Do it anyway ]   [ Use the fast one ]   [ Cancel ]
```

- The estimate is shown **even when no warning fires** — the number is wanted, not only the nag.
- Unmeasured card or model ⇒ `cost unknown on this machine` plus the count; never invented seconds.
- "Do it anyway" is remembered **for the session only**; tomorrow's answer may differ.
- Never blocks, never auto-switches, never hides Cancel.

## 7. Waves, and parallel safety

**Wave 1 — parallel, disjoint files.** Safe for subagents: one file each, no shared edits.
- **(A1)** `matrix.py` + `test_matrix.py` — the arithmetic, chips, sheet packing.
- **(A2)** `estimate()` — pure function over `deployments.py` data (`card, model, size → seconds or None`) + tests.
- **(A3)** read-only audit: every test or code path that asserts/toggles a control being moved; returns the exact list §6 needs. Scout, no edits.
- **(A4)** the doc skeleton in a **new** file.

**Wave 2 — serial, single owner of `zimage_ui.py`.** Picture and folder context menus (lazy) → remove pane/strip buttons with
their tests → matrix dialog over `matrix.py` → hunt warning over `estimate()` → delete the five inline matrix widgets.

**Wave 3 — parallel again.** README/STATE text, version bump, both suites + `docs_check`.

**Rules in every subagent brief:** never `git add -A`; one owner per file; branch `agent/<name>`; no concurrent suite runs (Tk
suites write temp dirs but timing checks skew under load); no edits to `group_prompts.py` or `sessions.py`; commit and push
per turn with the state note current; product work only — the lab's one-agent/one-inference rules are unaffected.

### Why the 4060 box gets no implementation — `[4060]`

The loop is bound by the model's turns, not by this machine: the suites run in 60–70 s, interactions in 2–270 ms. A second
box editing the same `zimage_ui.py` would gain no throughput and add the two-writer hazard this repo has already been bitten
by. Its job is measurement, where it is uniquely useful:

| # | task | acceptance |
|---|---|---|
| 7.1 | capture CPU / RAM / OS / driver (one-liners in `MACHINES-2026-11-02.md`) | the three blanks in that page are filled |
| 7.2 | `python tools/ux_timing.py --json ux-4060.json` | a JSON block in the same shape as this box's, gallery shape recorded |
| 7.3 | `llama-bench -m … -p 2048 -n 128` and again at `-c 16384` | TTFT and decode recorded with quant, `n_ctx`, threads, driver |
| 7.4 | **verify the hunt warning fires** — 5–6 strengths at 1024 px on a non-fastest model (≈12 min estimated) | the dialog appears, *Do it anyway* proceeds, Cancel returns to the same dialog state |
| 7.5 | read the dialog copy on that box's DPI/theme | every label legible, nothing clipped |

## 8. Decisions — open until answered

1. Folder-level commands on the title only (proposed), or also on folder tiles?
2. Does `Delete…` leave the pane button entirely, or keep one visible destroyer and drop the menu item?
3. Warning threshold: 10 minutes of extra estimated work, or "always warn above N renders at full size"?
4. Keep `[Use the fast one]` in the warning, or only *do-it-anyway / cancel*?
5. Confirm step 1 as the default (21 renders ≈ 5 min here, ≈ 50 min on the laptop, and the dialog says so).
6. Contact sheet default off — confirm, or default on when the count is a perfect square?
