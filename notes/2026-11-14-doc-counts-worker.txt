NOTE 2026-11-14 - the documents' counts are measured against the three window suites (0.32.0)

WHAT WAS ASKED
Add a documented-counts checker that measures the real total instead of trusting a number, wire it where the other
checks run, and prove it fails on a stale number and passes on a correct one. The measurement here is the suites'
own: `test_gallery_ui.py`, `test_sizing.py` and `test_tiles.py` are run once each and each prints its total.

WHAT WAS BUILT
- `check_doc_counts.py` runs the three suites (through `winproc.run`, which is this repository's rule and its own
  suite says so), reads the `<N> checks: <P> passed, <F> failed` line each now prints, adds them, then reads every
  count the documents state - `N checks`, `N tests`, `N passing`, `the suite is N` - in `README.md`, `docs/*.md` and
  `CONTINUE-HERE.md`. A disagreement prints the file, the line, the claim and the measured number with the offset,
  and exits 1. `--test-output <file>` reads a saved transcript instead (no suite is run at all), `--save <file>`
  keeps the transcript the totals came from, `--quiet` prints only what disagrees.
- The three suites print their own total, which they did not before: a `CHECKS` counter beside `FAILS`, and a line
  `%d checks: %d passed, %d failed` next to ALL PASS / the failure list. Counting PASS lines outside the suite was
  the alternative, and it would have been a second implementation of each suite's own arithmetic.
- A suite that fails or prints no total fails the run: a total taken from a red suite is not a number to hold a
  document to. That is why the run below ends 1.
- Wiring: README's "Running the toolchain" (the documented check list) has the two commands and says why the gate
  exists; `docs/STATE.md` - the durable record of what the tests enforce - gains the row that names it, so it is a
  decision on the page rather than a script nobody calls. `docs_check.py` still passes over the edited README
  (58 relative links, 0 failures, no forbidden marker).
- `version.py`: 0.31.0 -> 0.32.0 (a gate added = feature = minor).

WHAT IT FOUND, AND WHAT THAT COST
1. My first version called `subprocess.run` directly, and `test_gallery_ui.py`'s own check - "every subprocess call
   goes through winproc", which greps every root `*.py` - failed on it: `FAILURES: every subprocess call goes
   through winproc`. The gate caught the gate. Fixed by importing `winproc` and calling `winproc.run`.
2. `test_sizing.py` reports 1 failure of 209 on this box, in the checker's run and in a standalone run:
   `every pixel of the hit area belongs to the sash, and neither neighbour takes one`, detail
   `(['None', 'None', 'None'], ['None', 'None'])` - `winfo_containing` answers None for every probed coordinate, so
   no window of this application is at the sash's own root coordinates on this desktop. `notes/2026-11-14-sash-capture-and-coalescing.txt`
   records the same check PASSING at 0.31.0 in 77 s, and the only change this turn made to that file is a counter
   and a summary line, which cannot move a pixel. Not diagnosed further: it is a property of this desktop session,
   not of the counts, and the ticket was the counts.
3. Two false positives in the claim patterns, fixed before the run was believed: `18 prompts in 6 check categories`
   read as "6 checks" (now `checks?` may not be followed by a lowercase noun) and `3/3 passing` read as the suite's
   passing count (a number after a slash is a fraction of runs, not a count). And one silent FALSE NEGATIVE, which
   is the worse kind: `quoted()` counted apostrophes as quotation marks, so the first stale claim I planted in
   `docs/STATE.md` - on a line that begins "the documents' counts" - was invisible. It now counts only `"` and
   backticks.
