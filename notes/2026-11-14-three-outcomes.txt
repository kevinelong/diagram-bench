THE PRINCIPLE THIS TURN IS ABOUT
An unanswerable question must not be scored as a wrong answer, and a skipped check must not be scored as a pass.
Two outcomes for three kinds of result was the bug: the suite could only say "true" or "false", so a fact about the
desktop session had to be written down as a fact about the hit area. It now has three outcomes and reports each one.

WHY A SKIP IS NEITHER
- Not a pass: nothing was measured. Counting it as passed puts a check that never ran into the passing total, which
  is a false green - and `check_doc_counts.py` holds documents to that passing number.
- Not a failure: nothing about the code was found wrong. The suite's exit code is about the code.
- So it is counted apart (`SKIPS`), included in the suite's own size (`CHECKS`, because the check was asked), printed
  by name in the tail with the reason, and printed as a third number in the summary line. The gate reads the third
  number, sums it, and keeps it out of both of its own totals.
