## 1. The native port: parity that is started, not finished

The Rust prototype (`native/`) draws the gallery from real Win32 controls and now reviews and generates. What it does
**not** do is decide anything the Python app decides, which is the whole remaining distance.

| 1.9 | The Zig half | parked with its rationale in `native/README.md` | not planned. Listed so it is not mistaken for pending |

**Why 1.1 first**: everything the native app is missing is a *decision*, and every decision already exists in Python. Until
the port reproduces those decisions, two viewers of the same gallery disagree about what a folder is — which is the one
thing a second implementation must not do.

**Why 1.2 is small but real**: the divergence is 1 fixture of 4, and the fixtures are synthetic. Whether the bits agree on
real renders is unknown; that is a 20-line measurement followed by a decision.

## 2. Experiments planned, not run

### 2.1 The cost floor of every render (`--cache-none`)

Measured this session: the identical 256 px / 4-step job costs **20.9 s** natively and **32.4 s** through
`zimage_gen.py`, and the *server* is the floor — it runs with `--cache-none`, so every prompt reloads the model. Warm
runs cost the same as the first one, which is how we know it is not one-off loading.

Not run: the same job against a server started **without** `--cache-none`.

- Acceptance: three warm 256 px renders and three 1024 px renders on both server configurations, wall time each, VRAM/
  RAM recorded; then a written decision on whether the default changes (it trades memory for latency, and the memory gates
  are real: >= 9 GiB free physical, >= 8 GiB commit headroom).

### 2.2 Is 24 the right recency window?

`RECENT_POLICY = 24` was chosen by Kevin on 2026-10-30 to make a young gallery non-empty and a finished render visible.
Nothing measured says 24 is the right number.

- Acceptance: on the real gallery, the fraction of pictures that are inside the window but *not* in any family (the ones
  the window is hiding), at 12 / 24 / 48. If that fraction is negligible, the window could be larger — or the tile could be
  unnecessary. One query over the existing plan; not run because the order of work was "make it visible first".

### 2.3 The parked memory comparison

I offered a compare-mark/restart-measure experiment on the native prototype's memory, then did not run it once the
native and Tk apps were both under test in the same session. Not run.

- Acceptance: `WorkingSet64` after a cold scan of the real gallery versus after a settings change and restart, with the
  same gallery, twice each.

## 3. Questions this project has measured *around*, not answered

These are inherited from `README.md` § *What has not been established* and remain open; listed here because they are the
research, as distinct from the engineering.

- **Drawn labels inside diagrams do not bind.** A tree's leaves carry the prompt's own numbers instead of 1..7 at every
  density. It is a content failure, not a wording failure. The untried lever is a LoRA trained on our own corpus — no
  experiment started.
- **The fine anatomy tier is unvalidated.** Coarse 19/19, fine 9/9, but a judge that says yes to every digit question at
  704 px has not been shown to *count* fingers. Until it is, `fine_*` stays reported separately and never averaged in.
- **Blender (method D) was never run**; no animated asset has been scored.
- **Two prompt dimensions are recorded as unmeasurable**, not passed: dimension arrows on blueprints, and lane semantics.
- **FLUX.1-dev is blocked, not measured** (blurs at 1024, sharp at 512), and the VRAM floor is a distribution that names
  its resolution.
- **Determinism**: no diffusion arm is deterministic at a fixed seed, so cross-arm deltas under a few points are not effects.

## 5. Decisions taken *against*, and why

Recorded so they are not reopened by accident.

- **A path-aware session key.** The key hashes picture *names* (deliberately, matching the Python). Two folders with the
  same names therefore still share one session file; what is fixed (`69314dc`) is that the paths *stored inside* a session
  decide which folder it belongs to. Making the key path-aware would rename every existing session file and is not worth it
  while the guard holds.
- **Matching Pillow's dHash bit for bit.** Deferred, not refused (see 1.2). Implementing Pillow's resampling kernel is real
  work for an ordering hint.
- **No grouping by section headers, ever**, and never naming a folder after one. Stated as a rule in the README, enforced
  in `group_prompts`.
- **Tests write only to temp dirs** (`ZIMAGE_SETTINGS_DIR`, `pair_review.STATE_DIR` redirected at import). A test that
  writes `~/.local/zimage-ui/` is a regression, not a quirk.
- **The window never exceeds 60 % of the screen**; maximising is clamped rather than remembered as a size.

## 6. Order, by value

1. **1.1** native `group_prompts` parity — removes the only place where two implementations disagree about the gallery.
2. **1.2** dHash decision — 20 lines, and it makes the review order reproducible or explicitly not.
3. **2.1** the `--cache-none` experiment — every render in every app pays this floor; one experiment prices the alternative.
4. **1.3 / 1.6** native Describe-all and a warm thumbnail cache — the two gaps that make the native app feel like a
   prototype whenever there are many pictures.
5. **1.7** pane accessibility — the custom panes are the only controls a reader cannot describe.
6. **2.2** the recency window — cheap, and it closes a choice that currently rests on a decision rather than a measurement.
7. Everything in §3 is research, not a queue: it needs a hypothesis and a fixture before it needs an implementation.

## 8. Found after writing this page

- **The web app is behind the window** (from `web/README.md`, unchanged): no gallery mode (one picture at a time with
  Prev/Next), no recursive scan, no sort/filter/search, no source switching, no settings, and no per-picture "describe this
  one". Acceptance is the same behaviour as the window, checked by `web/test_web.py`.
- **Versioning is adopted in one project only.** The rule is in `~/.omp/agent/AGENTS.md` and applies everywhere, but
  `tek-tube`, `tc`, `textcrush-android`, `textcrush-ios`, `fc`, `score`, `ai_bench` and the rest still have no `version.py`
  and no corner label. Acceptance: each project, the next time it is touched, gets a single version constant, the label or
  the equivalent surface, and the same three-line rule in its README.
- **The combine path has no per-reference weight.** All references are chained at equal influence; there is no way to say
  "mostly this one". Not planned, listed so it is a known limitation rather than an oversight.

  button is disabled during it. Acceptance: Stop during the wait leaves the run cancelled and the server start unattended.
