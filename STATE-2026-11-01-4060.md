## Last turn (2026-11-02 ~08:06)

### Fixed an upstream bug that broke folders outright

`group_prompts.plan()` died with **`KeyError: 'man'`** on any gallery holding exactly **one distinct lineage root** —
which is what a one-picture gallery is. The app's own log recorded it three times
(`%LOCALAPPDATA%\zimage-ui\folder-events.log` → `{"ev":"error","detail":"KeyError: 'man'"}`), so folders never appeared.

Cause, `group_prompts.py:795`: when `len(root_list) > 1` the block above fills `families`, and the next line is a no-op;
with a single root that block is skipped entirely and `families.setdefault(i, text)` seeded the dict **keyed by the
index** (`{0: 'man'}`) while the lookup two lines later is **by text** → `KeyError`. Fixed to
`families.setdefault(text, text)` with a comment recording why it was invisible on the 5070 (that gallery always has
many roots).

Verified three ways: the repro script now returns `{'recent': 0, 'groups': 0, 'ungrouped': 1}` instead of raising;
`group_prompts.self_test()` passes; and the live app logged
`toggle → plan_cached(groups:1,files:2) → apply(groups:1) → heads_cached` with **no error**. The single picture now shows
as an `unfiled (1)` tile.

### Picker offered a profile that cannot render — fixed

Selecting `flux2 klein 9b uncensored` failed on Generate with `prompt_outputs_failed_validation`. The truncated JSON hid
it; the server log names all three: `vae_name 'flux2-vae.safetensors'`, `clip_name
'flux2-klein-9b-uncensored-te-q5_k_m.gguf'`, `unet_name 'flux-2-klein-9b-Q4_K_M.gguf'` — none on disk, since that
profile was deliberately never downloaded (8,837 MiB peak at 512 px > 8,188 MiB card). The app's own hint
("server has no model paths") is a misdiagnosis for this case.

Two fixes:

1. `zimage_gen.py`: the 9B profile gained **`'in_picker': False`** — the picker already honours that flag, so the entry
   and its measured numbers stay readable while the UI stops offering a choice that cannot render. `ALL_ORDER` updated
   to `['z-image turbo', 'flux3 klein 4b']`; every name in it must be a live `MODELS` key or `all_plan()` silently
   substitutes 4 steps and produces a render that fails validation.
2. `zimage_ui.py`: the saved picker value is honoured only if the picker can still offer it —
   `settings.get('model')` used to be restored verbatim, so a retired profile came back from `settings.json` and failed
   on the first Generate. Falls back to `DEFAULT_MODEL` otherwise; `ALL` is always allowed (a mode, not a profile).
   Confirmed live: closing the old window wrote `flux2 klein 9b uncensored` back into settings, which is precisely the
   value the new guard now rejects.

Verified: picker list is `['z-image turbo', 'flux3 klein 4b']`, `all_plan(512)` returns both at their own ceilings
(9 / 16 steps), every `ALL_ORDER` name resolves.
