So the transfer was three things, not fifteen. All three are in this commit.

## 1. `_visible_files` fetched every mtime twice

The walk returns `(path, mtime)` pairs; `_visible_files` threw the mtime away and the sort key called `f.stat()` per
picture. Measured on the real gallery, 3,224 pictures:

```
stat per file                    46.53 ms
sorted by fresh stat             49.23 ms
sorted by the walk's map          0.55 ms      (dict build: 0.14 ms)
```

One syscall per picture per refresh, for a value the walk had just read. The sort key now reads the map. The list is
byte-identical; the fallback to `stat()` only fires for a path missing from the map.

## 2. Six settings keys were written and thrown away

`_persist` wrote `steps_by_model`, `rephrase_intensity`, `rephrase_matching`; `save_settings` filtered the dict against
`SETTINGS_KEYS`, which did not list them, so all three died at exit and nothing said so. Registered, plus two new keys:

- **`sort`** - the picker survives a restart, but only a value the picker offers (`Recent`/`Wins`/`Sequence`), so a
  stale profile cannot put a word in the box nothing can re-sort.
- **`last_folder`** - the folder being read is reopened by name. Chosen by `restored_folder(plan, was_open, saved)`, a
  pure function: the open folder wins, the saved name is used only if it still exists in the new plan, and the key is
  removed from the settings dict after the first plan so a later re-group cannot drag the reader back.

**Not** remembered: the search box. A filter that survives a restart is how pictures look missing - the same reason the
chain box is deliberately forgetful.

## 4. Gallery mode is a real picture window

The one place where the Rust gallery was plainly ahead: its full-screen view is chrome-less, has a zoom ladder, drag-pan,
a slideshow and furniture that fades. Ours showed one picture, fit to the cell, with the bar always on. Added, all gated
on `_review_mode == 'gallery'` so the comparison window keeps its keys and furniture:

- **F11** toggles `overrideredirect` + screen geometry (and back to `state('zoomed')`); the picture is re-composed 120 ms
  later because the cell has no size until the frame is laid out. The chip names the state (`full screen` / `windowed`),
  and **Esc leaves full screen first**, the window second.
- **z** cycles fit → centred → original → 2× → 4×; fit scales up as well as down, matching the picture column's rule.
- **drag** pans only when the drawn picture is larger than its cell, clamped to the drawn size so no blank edge is
  reachable; a picture that fits refuses the drag rather than pretending.
- **a** / **±** cycles the slideshow off → 1 … 60 s, wrapping, and any manual step cancels it.
- chrome (bar + badge + chips) returns on motion or key and hides **2.5 s** after the pointer stops.

Mechanism, because it is the reason this was a small change: the picture is drawn **into a cell-sized image**, so the label
never resizes and nothing beside it reflows on a zoom change; a shrink of 2× or more takes one integer box reduction
before the smooth step (the main canvas's own pipeline); and the pan is a paste offset. Decoding happens once per
picture. Both timers are cancelled in `review_stop` - a pending tick would fire into a destroyed Toplevel.

**Verified** by a 20-check harness against a fixture gallery: chips gridded, the five-rung zoom ladder and the drawn
sizes it produces, full screen on and back off with Escape not closing the window, the slideshow advancing on its own
and stopping, the chrome hiding and returning, the drag panning only when the picture overflows, and both timers gone
after Stop. `test_review_modes.py` - **FAILURES: none** (rank/delete untouched); `test_gallery_ui.py` - **ALL PASS**.

**A bug the screenshot found, and the test that now catches it.** The first wiring of the five keys bound them through
`lambda e, f=fn: (f(), 'break')[1]` - the shape the comparison window's keys use - while the new handlers take an
*optional* event. Pressing F11 raised `TypeError: <lambda>() missing 1 required positional argument: 'e'` inside a Tk
callback, which is invisible to a test that calls the methods directly and only shows up as a dead key in use. Found by
`shots/60-gallery-fullscreen-2x.png` refusing to be about the gallery at all (the capture was of the main window
because nothing had happened), fixed by passing the handlers themselves, and pinned by
**`test_gallery_fullscreen.py`** - 28 checks, half of them driving **real `<KeyPress>` events at the window** and
reading the state back: `z` walks the ladder and the chip follows, `a` starts the timer, `F11` sets `overrideredirect`,
`Escape` clears it without closing the window, and `<Motion>` brings the chrome back. The other half pins the ladder
geometry (**2× is exactly twice the original, 4× four times**), that a picture which fits offers no pan, that rank mode
restores the pair and hides the chips, and that Stop cancels both timers. Three consecutive runs: **ALL PASS**.

Two captures are committed as the visual record: `shots/60-gallery-fullscreen-2x.png` (full screen with the chrome up)
and `shots/61-gallery-chromeless.png` (the same picture with the bar, badge and chips hidden - a picture on black and
nothing else).

**Still two panes:** `open_folder_browser` maximises with the folder tiles *beside* the open folder's pictures. A
single-pane, edge-to-edge folder grid is a separate, smaller decision - the same F11 handler would do for the frame, and
what is left is which pane gives way.

## 5. What this deliberately does not do


The two largest findings from the map are *not* in this commit, because each needs a design pass rather than an edit:

1. **Every `refresh_gallery` destroys and re-creates every visible tile widget.** Retained items (reconfigure instead of
   destroy/grid) is where a flicker-free strip and a cheaper refresh come from - and it is the same change the Rust app
   got for free by painting pixels instead of widgets.
2. **A `_photo_cache` miss decodes on the UI thread** (opens the thumbnail, `thumbnail()`s it). Prefetch covers the page
   ahead, not a resize sweep or a jump; the fix is the warm path `_warm_one` already demonstrates.

Both are listed here so the next session starts from the map rather than re-deriving it.
