## 2026-10-24: the base-image contract, and why a run uploaded an image with the box unticked

Reported symptom: the window sent an image to the model while *reuse last image as base* was unchecked. Cause, from the
code and from the sidecars in `Pictures/zimage-ui`: the old checkbox was read in one place only, *after* a run
(`zimage_ui.py`, the `chain_var` branch in `_poll`), where it promoted the finished image to base. What actually decides
an upload is `self.base_path`, and a **plain click in the strip** armed it as a side effect - `_on_tile_click` →
`select_file` → `_set_base` - so clicking a thumbnail to look at it, or to recover its prompt and seed, silently turned
every later Enter into an img2img at the saved strength (0.43 in that session). The session data shows the signature:
the 21:00:44 run carried base `...140529` **and that base's own seed 267546281**, which is `select_file` restoring a
seed, not a chained run.

Fixed by separating looking from editing:

- `select_file` no longer sets the base; it shows the picture and restores its prompt and seed, and the status line
  points at the new button.
- **Use as Base** (new, above Clear Base, enabled once a picture is shown) is the deliberate gesture: it arms the base,
  restores that image's prompt and seed, and says so.
- Ctrl+V still pastes *and* arms, because pasting is already an explicit "edit this".
- The checkbox is relabelled **chain: each new image becomes the next base**, and its tooltip no longer implies control
  over uploads.
- A run that uses a base now prints its age (`made 6h 51m ago`) in the hint line, so an old pick cannot be sent silently.
- The seed is kept through a run only while a base is armed; a click alone no longer pins it.

Verified: `test_gallery_ui.py` **310 PASS, 0 failures, exit 0** (drives the real window with a stubbed engine), with new
checks for "a click does not become the base", "Use as Base sets the base", "generate really passes it", "Clear Base
disarms it again", and "looking at an image does not pin its seed".

## 2026-10-25: which unfiltered klein is "stronger" - three arms on the frozen corpus

`generic_arm.py` gained the two arms plus `--host` (the server serving this box is on 8006, not 8188). Frozen corpus,
512 px, seed 1234, 10 prompts, RapidOCR scoring - one implementation, no opinion:

|---|---|---|---|---|---|---|---|

window four times a second during a render, the server launcher popped another, and the WSL `ffmpeg` call did too.
`winproc.py` now supplies `CREATE_NO_WINDOW` + a `SW_HIDE` STARTUPINFO, and every call site goes through
`winproc.run`/`popen` - twelve modules, including `prompts/selftest.py`. A test scans the sources and fails if a raw
`subprocess.*` call appears, which caught one I had just written. `start-comfy.ps1` launches with
`Start-Process -WindowStyle Hidden -PassThru`, redirects to `logs/comfy-<port>.{out,err}.log`, waits for the port and
**exits 0** - verified on port 8007 ("ComfyUI is up ... pid 315216"), then stopped. That also fixes the earlier incident
where a foreground `& $py @argv` died with its shell.

**Viewing the result, and knowing when it is done.** The bar is now determinate and fed by the same websocket the image
path uses, so during a clip the status reads `step x of 30` instead of a spinner. On completion the status reads
`clip done: <file>`, the hint gives frames, seconds, wall time, peak VRAM and the path, and the clip **opens by itself**;
**Open clip** reopens the last one without re-rendering.

## 2026-10-26: adverbs - why "culturally" and "explicitly" stay unmatched

Asked why those two words are skipped. Measured, and the answer is the dictionary rather than the matcher: `-ly` had no
rule, so no base was even tried, and when one is tried their bases (**cultural**, **explicit**) are not in it. Of the
**7** adverbs in the 20 real prompts, **0** have an adjective in the dictionary behind them, so adding the rule changes
no count today - but it makes the behaviour deliberate instead of accidental: `brightly` and `gently` were previously
being rescued by the *fuzzy* pass (one edit, loose), which is not a rule anyone chose.

So the stemmer now carries an **adverb** inflection: strip `-ly`/`-ily`, require the adjective to be a dictionary key and
at least four letters (so `family` is not cut to `fami`), and re-inflect the replacement the way English does -
`gentle -> gently`, `soft -> softly`, `basic -> basically`, `happy -> happily`. Verified: `softly lit room` becomes
`gently illuminated chamber`; `zorbly lit room` leaves `zorbly` alone.

Adding `cultural`/`explicit` to the dictionary was considered and rejected: their synonyms are not visual synonyms, and
"culturally diverse" becoming "societally diverse" changes what the prompt asks for. A no-op is the honest outcome.

Tests: **379 PASS / 0 failures**, with the adverb rule and its guard pinned.

## 2026-10-27, late: A4's three-frame fixture, and two exporter facts worth the trouble

`a4_fixture.py` runs inside Blender (`blender -b --factory-startup -P a4_fixture.py -- --out DIR`) and builds a
three-frame diagram: a border, a square that slides, a static square, a connector between them, and the words START and
END. `a4_check.py` scores the *output* - parse, structure, OCR, continuity - and exits non-zero on any failure.

**Two things about Blender's Grease Pencil SVG exporter had to be measured, not assumed**, and both cost a wrong
answer first:

1. **It ignores the scene camera.** No camera, an orthographic camera square-on to the stroke plane, and a camera
   turned 90 degrees produced byte-identical geometry: the exporter projects through a fixed oblique view. A square-on
   drawing therefore arrived rotated and skewed - the first render was a tilted parallelogram. The map is fixed, so it is
   *measured* here: nine probe strokes on a grid are exported and a homography is fitted to them. The residual is
   **0.000 px**, i.e. the model is exact for this exporter.
2. **It is perspective, not affine.** Before the homography, an affine (3x2) calibration left two identical squares at
   x = -3 and x = +4 measuring 94.0 px and 95.6 px in the same file - a 1.7 % error a linear fit cannot express. With
   the homography both read 95.0x95.0 px including their stroke width.
3. **The export canvas is content-relative** (crop to drawing, 10 px pad). Moving the object kept the leftmost pixel at
   10 px and grew the viewBox instead. A moving *label* therefore shifted the whole canvas between frames, which the
   checker caught as "every frame shares one canvas" failing at 502.8 vs 482.4 px wide; the fix is a border wide enough
   to contain every frame's content, and the checker still registers on the static square and reports its offset.

Also learned: the exporter writes stroke *ribbons*, not centrelines, so a probe's centre is the midpoint of its two
furthest-apart points; and Grease Pencil has no text, so glyphs are sampled from a font curve's own beziers - copying
converted point positions instead lost the curves and OCR read START as `TTART` and END as `EVD`.

Result: `ALL PASS`, `result-a4-fixture.json` in the fixture folder. This is the frame-level instrument the animation
protocol asked for; it is a fixture, not a claim about animation quality.

## 2026-10-28: arrow keys in all three lists, following the APG layout grid

**What was asked.** Keyboard navigation for the three lists that had none or had it badly: the left-column strip (both
modes - picture tiles, and folder tiles when folders are on), the `View All` window's `ScrollGrid`, and the two
`ScrollGrid`s in the prompt-folder browser. The owner named the convention: the W3C APG *layout grid* pattern.

**Why that pattern, and not "one index at a time".** A grid that steps a flat index makes Down wrap into a short last
row and Right stop dead at the row end. The APG pattern
(<https://www.w3.org/WAI/ARIA/apg/patterns/grid/>) is explicit about the asymmetry, and it is the asymmetry that makes a
grid usable: **horizontal movement wraps across rows, vertical movement never does**. Right on the last cell of a row
is the first cell of the next row; Left on the first cell of a row is the last cell of the previous row; but Down from
the last *full* row with a short row below it (7 pictures in 3 columns, column 2) moves **nowhere** rather than sliding
sideways into whatever cell happens to sit at that index. Home/End are the ends of the **current row**, Ctrl+Home/End
the ends of the list, PgUp/PgDn move one whole **visible set** of rows keeping the column, Space toggles, Enter
activates, Ctrl+A takes everything laid out, and Shift+arrows extend from the anchor the shift-click range uses.

**One implementation, three lists.** `grid_move(index, count, cols, move, rows)` is a module-level pure function: wrap,
clamp and paging cannot drift between the strip, View All and the folder browser because there is only one copy.
`grid_visible_rows(height, pitch)` derives the page size from the **measured** distance between two laid-out cells, so a
maximised window pages by eight rows and the strip by four. `grid_bind_moves(widget, handler)` binds the whole table -
plain and Shift- - on the widget, never with `bind_all`, so the prompt box, the View All search field and any dialog are
untouched by construction.

**Per-list semantics, where they honestly differ.** In the picture strip the cursor *is* the selection: that is how the
strip has always shown where you are, and it keeps the blue ring and the action buttons in step. In **folder mode** the
strip has one selection - the open folder - so a plain arrow only moves an accent ring on the outer frame of the folder
tile and Enter opens it; opening a folder on every arrow press would re-render the contents pane for movement alone. In
**View All** the selection must stay `App.selected`, because that is what Delete and Load read, so `ScrollGrid` reports
the intent (`on_mark(key, mode)`) instead of keeping a second copy. In the **folder browser** both grids keep their own
chosen set and paint a ring on the cell frame (accent, 3 px for the cursor, 2 px for chosen), because those tiles were
never registered in `_all_widgets`.

**Two invariants were kept rather than traded away.** A resize still never moves the view: `_see`/`_see_strip_cell`
scroll **only** when the cell under the keyboard is actually outside the viewport, and the strip's debounced
`_apply_strip_resize` / `_restore_scroll` path is untouched. And `test_gallery_ui.py` was run once as a regression guard
and left alone - 484 checks, `ALL PASS` - including its existing `_nav(0,0) / _nav(1,0) / _nav(0,1) / _nav_toggle /
_nav_open` expectations, which is why `_nav` still speaks `(dx, dy)` and delegates to `_nav_move`.

Deliberately not done: no new automated tests (the owner tests by hand), no vertical wrapping (the APG forbids it and
it would lose the column), no keyboard selection model for folder tiles beyond Enter/Space both opening.

## 2026-10-28, very last: a head count is a subject, so clusters are split by it

Kevin spotted "exactly Six adult women..." pictures inside the folder labelled "three very strong fit toned muscled...".
