## Where this stands in one paragraph

A local image-model instrument exists and has been exercised end-to-end: four methods (code→SVG, code→KiCad,
diffusion, cloud-vector-excluded), a frozen ten-prompt diagram corpus plus three hard pool-table tasks, twelve
scoring scripts with calibration histories, and **384 tracked files** in a git repo. The strongest measured result
is that **the prompt, not the model, was the lever**: a pool-table task went **2/7 → 6/7 → 9/11 → 10/11** across
four prompt revisions with the same model and seed. The last revision (**v5**) **regressed to 9/11**, and that
regression is the open thread.

## Established, with the numbers that matter

- **Method B (code→SVG)** is the best local route for teaching diagrams: labels **19/19** in source after one
  repair round, structure **44/57**, didactic **45/57**, editability total.
- **Method E (code→KiCad)** is the most exact and most fragile: **0/7 bare vs 6/7 with a template**, and it computed
  a **30°** cue where the SVG route drew a horizontal bar.
- **Diffusion**: Z-Image **0.811** labels at 1024 (13/20 perfect), klein **0.614**, schnell **0.552**; all
  non-deterministic; Z-Image's VRAM peak is a **distribution (433–1,062 MiB free)**, not a number.
- **FLUX.1-dev is unscored**: blurred at 1024 in six configurations, works at 512 but is mid-pack (0.704).
- **The prompt ladder** (pool table): 2/7 → 6/7 → 9/11 → 10/11 → **9/11 (v5 regression)**.
- **Prose constrains adjectives**: the rack became a triangle only when given as a lattice formula; the cue,
  still described in prose, is still inverted.

## Measured 2026-10-21: a numeric budget, and a matcher that was over-crediting labels

Same FLUX.1-schnell Q4_K_S arm, seed 1234, 4 steps, identical suffix and scorer; only the prompt text differs.
**The label matcher was wrong on the first pass** - `any(label in text)` credited `7` inside `70` and `120` inside
`1120`. Corrected to exact tokens and everything re-scored:

| prompt set | substring (retracted) | **exact token** | paths_median |
|---|---|---|---|
| frozen (one-liners) | 0.552 | **0.406** | 98 |
| grounded v1 (coordinates only) | 0.269 | **0.183** | 149 |
| grounded v2 (words + coordinates) | 0.437 | **0.337** | 104 |

Retracted on the correction: blueprint-1 v2 "2/2" is 0/2 (the reader saw `1120`), and tree-1 frozen "6/7" is
**1/7**. Ordering survives; two specific claims do not. **Every historical score in this repo used the substring
matcher**, so older `result-*.json` numbers are inflated wherever a required label is a short token or a digit.

**Numeric budget** (network-1, one unchanged target, only the count varying, exact token): 6 numbers **2/4**, 10
numbers **3/4** (peak), 18 numbers 2/4 **with coordinates printed as text** (`39910`, `11210`, `772`, `700`), 34
numbers 1/4 with corrupted labels (`P811`, `P822`). Predicted "flat to ~8, fall after 16" - half right: no plateau,
and the knee is at 10.

**Tree label binding is unsolved at every density.** frozen one-liner **1/7**, schema (51 numbers) 0/7, boundary (15
numbers) 1/7 with axis **100** - the render shows correct tree geometry whose nodes carry the prompt's own numbers
(`70`, `40`, `66`, `212`) instead of 1..7. So: density governs *structural* fidelity, and label binding fails
independently of it. Single-digit labels should be treated as **unmeasurable for this model** until something changes.

**Infrastructure**: the ComfyUI desktop app self-terminated ~30 s after start twice (auto-updater had queued desktop
1.1.7), killing a run mid-arm. ComfyUI's python server run directly on **port 8001** is stable and is what arms
should use (`COMFY_HOST`); the desktop app serves **8000**, not the 8188 the scripts assumed.
